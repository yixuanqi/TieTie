# 贴贴 v0.4.1 修复记录

## 反馈

Windows 实机已运行 v0.4，但从 PixPin 等工具复制截图后，界面提示“剪贴板里没有可读取的文字或图片”，实际上剪贴板并不为空。

## 根因

原先只使用 `arboard::Clipboard::get_image()`；它可能无法解码 PixPin 的 CF_DIB/CF_DIBV5 + BI_BITFIELDS 图像；再读取纯文本失败之后，代码误报“剪贴板为空”。

## 修复

1. 主面板 `paste` 事件优先读取 WebView2 直接提供的图片 Blob，使用新命令 `paste_image_data` 持久存储。
2. 系统级后台捕捉路径先调用 `arboard`，然后通过 Windows Clipboard 格式检测和 Windows Forms/GDI+ 兜底读取。
3. 支持将复制的单个 PNG/JPEG/BMP/GIF/TIFF 图片文件导入（文件列表优先场景）。
4. 解码大小检查、错误诊断增强、后台线程调用不阻塞前端。
5. 未改变用户数据目录、记录结构或应用标识，不需要数据库迁移。

## 验证

- `node --check web/app.js`：通过。
- `node --check web/float.js`：通过。
- `python tests/ui_smoke.py`：通过，包含 ClipboardEvent 图片导入（mock Rust API）、文字自动保存、搜索、Todo、悬浮窗口和双击隐藏。
- Windows/Rust 编译：当前环境无编译工具链，尚未验证。
